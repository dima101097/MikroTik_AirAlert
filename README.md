# AirAlert для MikroTik

Скрипт кожні 20–30 с запитує [Aerial Alerts API](https://wiki.ubilling.net.ua/doku.php?id=aerialalertsapi). Коли стан вибраної області змінюється, він запускає ваш скрипт тривоги або відбою. Поточний стан зберігається в глобальній змінній-прапорці, тому скрипти дій запускаються лише один раз на кожну зміну.

| Файл | Для чого |
| --- | --- |
| `airalert_v6.rsc` | Основний скрипт для RouterOS 6.43+ (запит по `http://`) |
| `airalert_v7.rsc` | Основний скрипт для RouterOS 7 (запит по `https://`) |
| `airalert_list.rsc` | Виводить у термінал усі області, їхній стан і рядок для копіювання |

API повертає назви областей кирилицею, закодованою як unicode-escape. У рядку RouterOS це пишеться з подвійним слешем: `\\u041a\\u0438\\u0457\\u0432` (Київ). Кирилиці в коді немає, тож Winbox її не зіпсує.

## Встановлення

1. Створіть основний скрипт. У Winbox: System → Scripts → `+`, Name `airalert`, Policy: read, write, policy, test. У поле Source вставте вміст `airalert_v6.rsc` або `airalert_v7.rsc`.
2. Створіть свої скрипти дій (назви мають збігатися з `scriptAlert` / `scriptClear`). Приклад:

```
/system script add name=airalert-on policy=read,write,policy,test source=":log warning \"TRYVOGA\""
/system script add name=airalert-off policy=read,write,policy,test source=":log info \"VIDBIY\""
```

3. Додайте запуск за розкладом:

```
/system scheduler add name=airalert interval=30s start-time=startup policy=read,write,policy,test on-event="/system script run airalert"
```

4. Перевірте, що все працює:

```
/log print where message~"AirAlert"
:global AirAlertState; :put $AirAlertState
```

## Налаштування

Усе, що треба міняти, знаходиться в блоці SETTINGS на початку скрипта.

```
:local region "kyiv"
:local scriptAlert "airalert-on"
:local scriptClear "airalert-off"
:local runOnFirstCheck true
:local apiUrl "https://ubilling.net.ua/aerialalerts/"
```

| Змінна | Що означає |
| --- | --- |
| `region` | Код області з таблиці нижче |
| `scriptAlert` | Скрипт, який запускається на початку тривоги |
| `scriptClear` | Скрипт, який запускається при відбої |
| `runOnFirstCheck` | `true`: після перезавантаження одразу запустити скрипт для поточного стану; `false`: лише запам'ятати стан |
| `apiUrl` | Адреса API: `http://` у v6, `https://` у v7 |

Глобальні змінні-прапорці:

| Змінна | Значення |
| --- | --- |
| `AirAlertState` | `alert`: тривога, `clear`: відбій, порожньо: після перезавантаження ще не було перевірки |
| `AirAlertChanged` | Дата й час останньої зміни стану |

```
:global AirAlertState
:if ($AirAlertState = "alert") do={ :log info "zaraz tryvoga" }
```

Щоб стежити за двома областями, зробіть копію скрипта і дайте глобальним змінним у ній інші імена (наприклад `AirAlertState2`).

## Діагностика і обмеження

| Повідомлення в лозі | Причина і що робити |
| --- | --- |
| `unknown region code` | Код у `region` написано з помилкою. Скопіюйте його з таблиці |
| `API request failed` | Немає інтернету чи DNS, або API повернуло 429 |
| `not found in API response` | Назва в API змінилась. Запустіть `airalert_list.rsc` і візьміть новий рядок |
| `script '...' not found` | Немає скрипта з назвою з `scriptAlert` / `scriptClear` |
| `error in script ...` | Помилка у вашому скрипті дії |

- API дозволяє до 2 запитів на секунду з однієї IP. Якщо ліміт перевищено, воно повертає 429 і може забанити назавжди.
- Після перезавантаження глобальні змінні скидаються. Далі все залежить від `runOnFirstCheck`.
- Для RouterOS 6 потрібна версія 6.43 або новіша.
- Автори API попереджають, що воно лише інформаційне.
